# Engineering standards

Read before writing code. Code quality wins over deadlines in this project.

The goal: anyone can open any file and understand what it is for and roughly how it works, without having to understand the code around it.

## Clean code

- **One job per file and per function.** If a name needs "and" to be honest, split it.
- **Names carry the meaning.** File, function and variable names say what they are and why they exist. No header comments per file; if a file needs one, its name or its scope is wrong.
- **Comments explain why, never what.** Use them for non-obvious constraints, trade-offs and workarounds, not to narrate code.
- **Small functions, flat control flow.** Prefer early returns over nesting. Keep functions short enough to read without scrolling.
- **Explicit dependencies.** A function gets what it needs through its arguments or imports, not through hidden global state.
- **Business logic is pure and framework-free.** Grading, scoring and validation are plain TypeScript functions that know nothing about Convex, React or Next.js. Convex functions and React components are thin glue that call them.
- **No dead code, no speculative code.** Build what the current milestone needs; delete what is no longer used.
- **Types document intent.** Name domain types (`Question`, `TeamAnswer`) instead of repeating inline object shapes; avoid `any`.

## Tests

- **Colocated:** every code file `foo.ts` / `Foo.tsx` has a `foo.test.ts` / `Foo.test.tsx` next to it.
- **Coverage threshold: 80%** (lines, branches, functions, statements), enforced in the Vitest config so the test run fails below it.
- **Tests read as documentation:** `describe` the unit, and name each case after the behaviour it checks ("gives 3 points within ±1").
- **Tools:** Vitest; `convex-test` for Convex functions (in-memory database, edge-runtime environment); React Testing Library for components.
- Convex skips any file in `convex/` whose name has more than one dot, so `*.test.ts` files there are never deployed.

## Exceptions

Exceptions to the test rules are made on purpose and listed here with a reason. The same list is excluded from coverage in the Vitest config; keep the two in sync.

| Path | Reason |
|---|---|
| `convex/_generated/**` | Generated by `npx convex dev` |
| `src/components/ui/**` | shadcn/ui components, vendored library code |
| `*.config.*`, `next-env.d.ts` | Tool configuration |
| `src/app/layout.tsx` | Root shell with providers only, no logic |
| `src/app/ConvexClientProvider.tsx` | Wires the Convex client, no logic |
| `**/*.d.ts`, type-only files | No runtime code to test |
